Shaders.cpp
🔴 Bug 4 — Reveal blend comment contradicts the actual Vulkan blend state
glsl// Reveal: the blend state is (ZERO, ONE_MINUS_SRC_ALPHA)   ← WRONG
// so src_alpha is what drives the multiplicative accumulation
outReveal = opacity;
The actual blend state configured in Vulkan.cpp is:
cpprevealBlend.dstColorBlendFactor = VK_BLEND_FACTOR_ONE_MINUS_SRC_COLOR; // not SRC_ALPHA
These are not equivalent. ONE_MINUS_SRC_COLOR uses the R channel of the source (= opacity, written by out float outReveal), giving (1 − opacity) × R_dst — which is the correct WBOIT product accumulation. If the blend were changed to ONE_MINUS_SRC_ALPHA to match the comment, the source alpha for a float output is effectively 0, so the factor becomes (1 − 0) = 1 and the reveal buffer never changes from its clear value of 1.0 — making alpha = 1 − 1 = 0 in the resolve pass and all transparency vanishing. Fix the comment:
glsl// Reveal: blend is (ZERO, ONE_MINUS_SRC_COLOR).
// R_dst = (1 − R_src) × R_dst = (1 − opacity) × R_dst
// Accumulated across N fragments: product(1 − opacity_i)
outReveal = opacity;
🟠 Bug 5 — OIT weight floor is non-zero
glslfloat weight = clamp(pow(opacity, 4.0) + 0.01, 0.001, 300.0);
The + 0.01 constant means every fragment, even one at the opacity discard boundary (≈ 0.05), gets a weight of at least ≈ 0.0101. This biases the weighted average in the accum buffer toward low-opacity fragments. A depth-based weight (standard McGuire–Bavoil) avoids this and gives order-correctness across depth:
glslfloat z    = gl_FragCoord.z / gl_FragCoord.w;  // view-space depth
float weight = clamp(pow(min(1.0, opacity * 10.0), 3.0) *
               1e8 * pow(1.0 - z * 0.9, 3.0), 1e-2, 3e3);
